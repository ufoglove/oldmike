# QualityPolicy：SLO、科研保真與處置政策

## 1. 服務水準目標 (SLO) 與門檻
- **當前狀態**：沿用 R02 提出之 `PROPOSED_SLO`。未經長期真人採用前不虛構 99.9% 或 24 小時承諾。
- **使用者導向**：SLO 聚焦於「使用者關鍵旅程（保存、恢復、匯出、審閱）」而非純主機 CPU/Uptime。
- **錯誤預算邊界**：
  * **可消耗 Error Budget 範圍**：API 瞬時延遲、受控重試、非關鍵性排隊延遲。
  * **嚴禁使用 Error Budget 抵銷**：跨專案越權、Raw Data 被改、Result Fact 篡改、未授權對外送件。上述事件一律以 P0 事故處置。

## 2. 確定性科研保真政策 (Fidelity Policy)
- **核心保護維度**：
  * **$N$ 與分母**：規劃 $N$ 不得在起草中被改稱觀察 $N$；各組別样本數不得互換。
  * **統計顯著性與方向**：未顯著（$p > .05$）必須如實保留，嚴禁潤色為顯著或有利方向。
  * **非測量機制**：未納入測量之變數僅能列為競爭解釋或研究限制，不得宣稱「機制已證實」。
  * **引用綁定**：文獻引用必須回溯原始 `CitationSource`，禁止 AI 自行填補不存在之文獻。
- **防禦機制**：
  * 攔截「token 存在但群組互換」、「$p$ 值保留但結論相反」等語義缺陷。
  * 確定性檢驗失敗時直接阻擋寫入，不可由 LLM 自評覆寫。

## 3. 樣本不足與資料不足處理
- **觀察不足原則**：當缺乏足夠真實操作事件時，狀態標記為 `INSUFFICIENT_OBSERVATION`，並如實揭露觀察區間與事件數。
- **嚴禁插值造假**：不使用模擬數據充填真實營運指標；合成測試（Synthetic Test）僅能用於驗證控制邏輯，不可作為營運健康之證明。
