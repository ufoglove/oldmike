## 1. 目標、前置文件與範圍

把登入後首頁做成「研究工作台」，讓使用者能清楚回答：我在哪個專案、目前做到哪裡、下一步做什麼、每項功能能幫什麼忙、產出存在哪裡。

優先讀取 repository 內實際的 PROJECT_STATE.md，並參照已提供的：

- OpenClaw_Research_Site_V3_Stage01_Foundation.md
- OpenClaw_Research_Site_V3_Stage02_Radar_Inspiration_TopicLab.md
- OpenClaw_Research_Site_V3_Home_Project_Controls_Addendum.md

若文件路徑不同，搜尋實際位置，不假定固定路徑存在。保留已有功能，不因本文件改掉其 ID、資料關係或研究流程版本。

本輪必做：首頁資訊架構、意圖入口、六群功能導覽、統一功能說明、可跳過的新手導覽、下一步卡片、可理解的流程、近期成果摘要、老麥情境協助、手機與鍵盤操作。

本輪不新增：完整投稿導航引擎、統計引擎、全文生成引擎、第二套文獻庫、新 Zotero 同步器、外部付費服務、Telegram 通知或不明 Skills。既有相關功能可連接，未建置就如實顯示。

## 2. 先盤點，不把建置狀態當研究進度

盤點首頁、Project Context、儲存／讀取、未完成專案清單、回收筒、模組註冊、路由、StageDefinition、ProjectStageState、AgentJob、產出版本、既有說明與文獻中心。

逐項記錄「已可重用／故障待修／尚未建置」，再做最小修改。以隔離開發／測試環境執行，保留未提交修改。正式 migration、正式部署、破壞性操作與新費用另需授權。

四種狀態不能混用：

1. 模組能力：可使用、尚未建置、維護中、外部設定待補。
2. 專案研究進度：未開始、進行中、完成、需修訂、不適用。
3. 內容狀態：草稿、機器檢查、人工核准、來源過期。
4. 操作權限：可閱讀、可起草、可執行、缺少授權。

不要在普通首頁同時展示全部內部 enum；用簡短中文標籤，細節放入「查看原因」。

## 3. 首頁有不同使用情境，但只有一套資料與路由

| 情境 | 首頁主要動作 | 次要動作與限制 |
|---|---|---|
| 初次使用且沒有專案 | 建立研究專案 | 可看功能導覽、使用已存在的獨立文字工具；不用假進度或示範文獻填滿首頁。 |
| 已有專案、未選定 | 從最上方清單選取專案 | 不偷偷選另一專案承接任務；可依既有規則恢復最後有效專案。 |
| 已選定進行中專案 | 繼續目前最合理工作 | 顯示儲存狀態、目前階段、具體下一步及理由。 |
| 任務正在執行 | 查看進度或已完成部分 | 不能用另一個「開始」重複啟動同一工作。 |
| 任務失敗或需要補資料 | 恢復／補齊具體缺項 | 顯示局部成果、原因與安全重試，不只有「稍後再試」。 |
| 只要翻譯、潤稿或整理已有稿件 | 開啟已存在的獨立工具 | 不強制先走雷達、IRB、Pilot。此操作不使正式研究進度自動完成。 |
| 完成／封存專案 | 查看成果或繼續修訂 | 不自動重啟研究、付費任務或外部送件。 |

說明詳略可以提供「顯示功能說明」開關，預設對新使用者開啟；不因此重排導覽位置或省略安全與資料狀態。偏好按使用者保存。

## 5. 保留四項已指定操作，不再另造一套

### 專案儲存、讀取與切換

沿用同一後端持久儲存、版本檢查與 Project Context。只有後端確認才顯示「已儲存」。可見狀態含尚有變更、儲存中、已儲存、部分成功、失敗、版本衝突。

最上方下拉只預設列出具權限且未完成、未封存、未回收專案；包含暫停與需修訂。搜尋、排序及「所有專案」入口沿用既有功能。

未儲存即切換／重新讀取，沿用「儲存後繼續／放棄本地變更／取消」。儲存失敗留在原專案。切換失敗不可新標題配舊內容。任何遲到任務結果不能寫入另一專案。

### 研究進度與路徑

只讀取既有後端流程摘要，不在首頁重新計算另一套數字。顯示計算口徑、已完成／適用階段數、更新時間；未知顯示未知。

### 底部刪除

保留醒目紅色警示區與「刪除本專案（移至回收筒）」。不做浮動刪除、不放進主要行動、不放在儲存旁。沒有專案或刪除權限時禁用並說明。

確認對話框顯示專案名稱；可復原、不永久刪除、不刪共用文獻或 Zotero 項目。任務回寫再次檢查已回收狀態，不能復活專案。復原不自動重啟外部任務。

## 6. 用使用者目的導覽，不要求先懂模組術語

建立下列六個意圖入口。入口只引導到既有能力，不在首頁重做研究引擎。

| 使用者看到的入口 | 一句解說 | 建議目的地 |
|---|---|---|
| 找研究靈感 | 從領域或關鍵字找機會，比較可以研究的題目。 | 前沿雷達／一鍵靈感／選題實驗室 |
| 查文獻與找缺口 | 整理本專案文獻，了解已有成果與尚未解決的問題。 | 文獻與證據中心／Gap與新穎性 |
| 準備研究計畫 | 選擇申請路線，整理國科會或教學實踐計畫內容。 | 投稿導航的計畫入口／適用工作室 |
| 分析研究資料 | 檢查資料與分析計畫，再用正式分析產生結果與圖表。 | 資料治理／分析實驗室 |
| 撰寫或修訂論文 | 用證據與結果建立全文，或檢查自己的現有稿件。 | 全文工作室／自稿科學審查 |
| 翻譯與學術潤稿 | 翻譯中英文與改善表達，保留數字、術語與引用原意。 | 翻譯與潤稿 |

探索群組保留既定三入口：「看前沿」「給我靈感」「我有想法」。不要在首屏再加一整排同樣功能。

「分析研究資料」沒有正式資料時，導向資料準備說明或分析計畫，不直接生成結果。

「撰寫或修訂論文」若有現有稿件，沿用既有匯入／審查入口，不強制重跑全部研究；匯入文件是作者提供材料，不自動驗證其數據或核准狀態。

獨立文字工具沿用既有私人草稿／工具工作區；無此能力則顯示尚未建置，不臨時建立未受權限控制的匿名資料庫。未選專案時先說明保存位置；使用者之後可明確指定保存至哪個專案。不得自動把文字當成本專案正式證據。

## 7. 六群完整功能地圖：分類與研究流程分開

分類是用來找功能，不是強迫所有人依序通過六關。穩定保留名稱、順序及路由；「與目前工作相關」可突出，但不能把其他群組偷偷移位。

| 群組 | 模組 |
|---|---|
| 探索與選題 | 前沿雷達、一鍵靈感、選題實驗室、投稿導航 |
| 文獻與研究規劃 | 研究藍圖、文獻與證據中心、Gap與新穎性、理論與機制、研究設計 |
| 計畫與研究執行 | 國際期刊研究規劃、國科會一般研究計畫、教育部教學實踐、倫理／IRB、工具與Protocol、Pilot、正式研究 |
| 資料與分析 | 資料治理、分析計畫、分析實驗室執行模式、結果與圖表 |
| 寫作與品質 | 全文協作、自稿科學審查、翻譯與學術潤稿 |
| 投稿與修訂 | 最終投稿規範、投稿文件與包、投稿追蹤、Reviewer回覆、修訂與成果管理 |

以下為全程共用工具，使用快捷連結，不複製資料或模組：文獻與證據中心、老麥協助、任務與成果、說明／回收筒。

作者自己的稿件修改、外部受邀審稿須用不同文案。若已存在「審查他人稿件」，放在工具清單，標記保密與處理授權限制，不與本專案 Author Response 或自稿修改混在一起。本輪不新增該專業引擎。

## 8. 每項功能都有同一格式的說明

每張功能卡預設顯示：

- 功能名稱：繁體中文為主，必要時英文副標。
- 一句話用途：描述能完成什麼，不只寫「智慧分析」。
- 產出摘要：例如「候選題、比較表與下一步」。
- 真實可用狀態。
- 具體行動按鈕，例如「產生候選題」，避免全站都叫「開始」。
- 「使用說明」入口。

點擊說明後，以側欄或可展開區顯示：

1. 適合什麼情況使用。
2. 需要提供什麼；已存在資料明示「已帶入」，缺少資料明示缺項。
3. 三個簡短操作步驟。
4. 會產生什麼與保存在哪裡。
5. 接續哪個功能。
6. 關鍵限制、證據狀態、外部傳輸或費用提示（適用時）。

用途、主要產出與必要警示不可全部藏在問號或hover；次要示例與專業細節才收合。[S2]

### 必須提供的解說種子

| 功能 | 一句話用途 | 應出現的產出說明 |
|---|---|---|
| 前沿雷達 | 區分目前熱門與未來新興，發現值得追蹤的研究方向。 | 有來源、日期與範圍的研究機會；不是保證未來預測。 |
| 一鍵靈感 | 把研究領域或機會轉成可比較的候選題。 | 候選題、初步RQ、資料需求與風險；新穎性仍需驗證。 |
| 選題實驗室 | 比較候選題的貢獻與可行性，選定值得進一步研究的題目。 | 選題快照、理由與待補資料；不是錄取率。 |
| 投稿導航 | 依研究內容比較目標期刊及研究計畫路線。 | 候選期刊／學門與規範缺項；不是正式投稿或核定。 |
| 文獻與證據中心 | 集中搜尋、閱讀、分析及引用本專案文獻。 | 專案文獻列表、Evidence與引用來源；可連結Zotero。 |
| 研究藍圖 | 把題目、目標與資源整理成可執行研究總計畫。 | 研究目的、RQ、規劃與版本；未執行內容仍標示規劃。 |
| Gap與新穎性 | 比較最相近研究，確認研究缺口及新增貢獻。 | Gap證據、相近研究矩陣、差異與不確定性。 |
| 理論與機制 | 說明研究現象為何可能發生，連結構念與研究問題。 | 理論依據、機制模型、假設或研究命題。 |
| 研究設計 | 決定如何取得可回答研究問題的資料。 | 設計、測量需求、樣本依據及分析計畫。 |
| 計畫書工作室 | 依選定路線整理申請內容，檢查缺漏。 | 計畫書草稿、工作包與附件準備；不等於申請通過。 |
| 倫理／IRB | 管理適用倫理規劃、機構文件與研究執行限制。 | 文件與授權狀態；網站不自行宣布核准或免審。 |
| 工具與Protocol | 管理研究工具、授權、評量與操作流程。 | 工具版本、計分規格與Protocol。 |
| Pilot | 預試研究工具與流程，找出正式研究前的問題。 | 預試證據、修訂決策與Protocol更新；不是正式效果驗證。 |
| 正式研究 | 管理授權範圍內的研究活動及原始資料來源。 | 執行紀錄與Raw Data來源；不自動生成參與者。 |
| 資料治理 | 在保留原始資料的前提下整理可追溯分析資料。 | 清理規則、資料字典、Analysis Dataset及來源鏈。 |
| 分析實驗室 | 依分析計畫處理真實資料並保存可重現結果。 | 分析紀錄、結果與圖表；無資料不產生正式結果。 |
| 全文協作 | 用文獻、方法與真實結果逐章建立或修訂論文。 | 章節版本、數值與引用追溯；草稿不等於正式送件。 |
| 自稿科學審查 | 從模擬審查者角度檢查自己的研究與論述。 | 問題、證據與修訂任務；不是期刊官方意見。 |
| 翻譯與潤稿 | 改善中英文表達，同時保留科學含義。 | 對照稿、術語與修訂版本；不保證投稿接受。 |
| 投稿規範與文件 | 依期刊當下規範核對主文、聲明與附件。 | 投稿包與缺漏清單；只有真實回執才算已投稿。 |
| Reviewer回覆 | 拆解真實審查意見，追蹤逐條修訂與回覆。 | 回覆矩陣、修訂稿與版本位置。 |

以上為可編輯說明種子，不代表相關能力已實作。以真實模組註冊及測試狀態控制可點擊性。

## 9. 功能搜尋與共用說明來源

沿用或擴充 ModuleRegistry／Capability Registry，不建立另一個與實際路由無關的手寫首頁選單。

說明資料最少含：module_id、group_id、display_name、plain_summary、when_to_use、required_inputs、outputs、steps、limitations、action_label、route_ref、standalone_supported、help_version、owner／verified_at。

能力狀態、權限與專案缺項須從即時狀態解析，不能永久寫死在說明文案。以同一份資料供首頁卡片、側邊選單、搜尋、說明抽屜與老麥功能解說使用。

搜尋第一版以功能名稱、同義詞與已驗證說明本地索引即可，不需要每次呼叫付費LLM。例：「沒有靈感→一鍵靈感」「找文獻→文獻與證據中心」「選期刊→投稿導航」「中翻英→翻譯潤稿」。

搜尋結果顯示用途、所在群組與狀態；無結果顯示可嘗試的詞與完整功能清單，不杜撰新功能。只查功能說明，不混入跨專案私人稿件全文搜尋。

「尚未建置」可打開說明，不可跳空白頁；「需要先完成X」可閱讀及在授權範圍內起草，不可繞過研究執行條件；「服務未連接」只阻擋依賴該服務的動作。

## 10. 整體路徑與下一步：不是二十個硬性線性步驟

首頁六群流程用來定位，完整路徑用樹狀／分支清單呈現，保留文字狀態與可到達連結。不要使用只能線性前進的step indicator當作整個科研流程導航；USWDS亦區分線性步驟指示與非線性、條件分支流程。[S3]

Publication Route與Funding Route分開呈現。國科會一般研究計畫／教學實踐是計畫路線，期刊是發表路線，可以並存；計畫書準備不應被推到實驗結束之後。資料、倫理與規劃的具體相依沿用後端，不因首頁分群就創造新Gate。

整體進度沿用現有workflow_version與適用階段。首次沒有規劃時顯示「尚未建立研究路徑」，未知不是0；不適用階段有理由，未建置但適用階段不能偷偷排除分母。保存、看過說明、看完導覽與程式測試成功均不提高研究完成率。

下一步只突出一個主要行動，必須可追溯到真實任務、來源版本與阻擋原因。優先依序：

1. 當前操作有保存失敗／安全或權限阻擋：先處理真正阻擋。
2. 有工作執行中：查看進度與已完成部分，不重跑。
3. 有未完成且仍可操作的目前工作：繼續該工作。
4. 有有效下一個必要任務：開始該任務。
5. 專案完成：查看成果；沒有專案：選取或建立。

「下一步」從後端既有狀態或規則解析。老麥可解釋理由，不能自行把缺失權限、IRB或分析結果改成通過。回訪時讀取最新狀態；若正在操作中有新提醒，不突然重排焦點或把按鈕替換成另一項動作。

每張下一步卡清楚顯示：目前工作、為何建議、已帶入資料、缺項、會產生什麼、保存位置。

## 11. 新手導覽、情境解說與老麥協助

提供常駐「功能導覽／使用說明」，同一畫面系列位置保持一致。[S4]

第一次登入只提供小型導覽邀請，不強制全螢幕教學。導覽最多四個重點：選取專案、看路徑／下一步、找功能與說明、找成果與儲存狀態。可跳過、關閉、重看、用鍵盤操作。

導覽不能自動建立真實專案、發起搜尋、付費、同步Zotero或執行刪除。示範資料隔離且明確標記。完成導覽只更新tour_seen_version，不更新研究進度。

同一tour版本不每次登入強制重播；更新只提示重大差異。路由或元件未建置時跳過不存在的步驟，不把遮罩鎖死。

每個模組頁面沿用一句用途＋已帶入資料＋下一動作＋返回專案。說明內常見問題包含：功能差異、資料保存位置、為何不能執行、Zotero斷線影響，以及草稿與正式研究結果的差別。

老麥協助以目前project_id、module_id、權限、狀態及同一份功能說明作為上下文，支援「這個功能做什麼」「我現在該做哪一步」「為什麼暫時不能用」。無法查到能力時如實回答，不猜介面或承諾尚未建置功能。

老麥聊天綁定專案；切換時依既有隔離機制更新。前台以老麥呈現，但外部資料處理、工具費用與必要AI使用揭露不得因品牌隱藏而隱瞞。

## 12. 近期成果、文獻摘要與提醒

首頁不是文獻中心副本。只顯示輕量摘要及深連結：專案文獻數、待補引用、全文閱讀狀態、Zotero最後成功同步及失敗狀態。書目核對、已讀全文、Claim支持及Zotero同步不互相等同；同步失敗不能把本地已存在文獻顯示成零。

近期成果預設顯示少量最近版本，包含標題、類型、實際更新時間、草稿／核准狀態與開啟入口。沒有就顯示「目前尚無成果」與合適下一步，不做假示例。所有深連結保留project_id、artifact_id及版本，並驗證後端權限。

提醒按阻擋、需處理、一般資訊分級；只顯示與目前任務相關者。外部來源失效、未儲存內容與服務錯誤不得藏在說明中。保存成功與任務狀態需可由輔助技術取得，但避免每個字的串流都重複播報。[S5]

不要讓首頁每次開啟都重新跑期刊檢索、整庫Zotero同步或付費生成。需更新的摘要使用既有快取與實際updated_at；過期就顯示過期。

## 13. 視覺、手機與無障礙

沿用既有設計系統，只調整層級、留白與一致性。主要行動最突出，其餘用次要樣式；紅色保留給真正錯誤／危險操作，不到處用紅色當裝飾。

中文標題優先；不要求使用者先理解Gate、Protocol、Evidence等術語。必要時附中文解釋。圖示一定搭配文字，研究狀態不能只靠色彩。

建議設計目標：主要觸控按鈕至少44×44 CSS px；這是本產品較易操作的設計選擇，不是將WCAG 2.2 AA最低要求誤寫為44。SC2.5.8的最低目標尺寸為24×24 CSS px並有例外，按實際條件驗證。[S6]

測試至少320 CSS px重排、常用手機寬度、平板與桌面；首頁不應靠整頁橫向捲動找功能。真有二維內容的局部區塊另提供可理解呈現。[S7]

鍵盤可使用下拉、搜尋、卡片連結、展開說明、對話框及導覽。Focus清楚；抽屜關閉後回到觸發元件。頂部黏性專案列與老麥面板不能遮住聚焦元件；手機鍵盤打開時也測試。[S8]

Help卡不只靠滑鼠hover。減少非必要動畫，遵守使用者減少動態效果設定。不要為了炫技加入持續閃爍、旋轉雷達背景或不可關閉導覽。

## 14. 資料、可靠性與安全

優先擴充既有registry 與 API，勿為每一張卡新增資料表。可能需要的內容僅為：功能說明版本、使用者導覽偏好、權限過濾的Dashboard摘要，以及安全的既有深連結。

所有project相關讀取由後端檢查權限；UI隱藏不等於授權。讀取首頁本身不啟動模型生成、修改研究狀態或付費任務。點擊說明也不觸發隱藏工作。

長任务沿用AgentJob及恢復機制。開始按鈕冪等、取消可查、失敗保存局部成果。路由與查詢快取包含workspace／user及project_id，避免A專案遲到結果出現在B。

不得為功能解說將完整研究稿件、憑證或參與者資料送往外部服務。使用既有批准的語言與研究服務；超預算、外傳、永久操作與送件仍採既有保護。一般草稿、建議與版本保存不逐段強制確認。

A. 盤點與相容：畫出現有首頁、模組路由和專案狀態映射，保護資料，確認四項原有控制不回歸。

D. 驗收與交付：桌面／手機／鍵盤、不同專案與錯誤情境測試，更新PROJECT_STATE.md。
